# instytut.14-200.pl

Static website of **Iławski Instytut Idei**, migrated from Google Sites.
Built with [Eleventy](https://www.11ty.dev/), plain HTML + one small CSS file, no frameworks or webfonts.

```sh
npm install
npm start        # dev server on http://localhost:8080
npm run build    # output in _site/, then regenerates vercel.json
```

## Hosting

- **Vercel**, static only (no functions). Project settings come from `vercel.json`; keep the dashboard fields empty.
- Domain `instytut.14-200.pl`. DNS is in Cloudflare (zone `14-200.pl`): `CNAME instytut → cname.vercel-dns.com`, **DNS only** (grey cloud), so Vercel issues the certificate.
- `vercel.json` is generated by `scripts/vercel-config.mjs` from `_site/_redirects` after every build. Vercel reads it from the repository, so **commit it** when the build says "updated".
- The same `_site/` also works on Netlify / Cloudflare Pages (they read `_redirects`).

## Editing in the browser

`https://instytut.14-200.pl/admin/` runs [Sveltia CMS](https://github.com/sveltia/sveltia-cms) (config: `src/static/admin/config.yml`).
Every save is a commit to `yasiupl/instytut.14-200.pl` on GitHub, and Vercel deploys it in about a minute.

- Editors need a GitHub account with write access to the repository.
- Sign in: "Sign In with Token" with a fine-grained GitHub token (repository: this one; permission: Contents read/write).
- Optional "Sign In with GitHub" button: deploy [sveltia-cms-auth](https://github.com/sveltia/sveltia-cms-auth) as a Cloudflare Worker and set `backend.base_url` in the config.
- Uploaded images are converted to WebP, max 1600 px, like the rest of the site.
- Pages (`src/pages/`) can be edited but not created or deleted in the CMS: their addresses are linked from everywhere.

## Layout

| Path | What |
| --- | --- |
| `src/aktualnosci/*.md` | News posts → `/aktualnosci/<slug>/`, listed on home, `/aktualnosci/` and in the feeds |
| `src/projekty/*.md` | Projects → `/projekty/<slug>/`, listed on `/projekty/` |
| `src/pages/*.md` | Standing pages (Laboratorium, Pracownia, O nas, Kontakt…) |

Front matter: `title`, `date`, `summary` (one line for lists), `image` (thumbnail), `area: "lab" \| "pracownia"`, `redirect_from`.
| `src/_data/site.js` | Site config: nav, contact, rel=me links, webmention + fediverse settings |
| `src/_includes/` | `base.njk` (shell), `page.njk` (article / h-entry), `home.njk` (h-feed) |
| `src/assets/` | `style.css`, `site.js`, images (WebP, ≤1600 px) |

Shortcodes inside Markdown: `{% youtube "ID", "title" %}`, `{% form "url", "title" %}`.

## Old URLs

Every Google Sites path is kept. A page's `redirect_from` produces:

- `_site/_redirects`: 301s for Netlify / Cloudflare Pages (both raw and percent-encoded Polish characters);
- an HTML `meta refresh` stub at the old path, for hosts that don't read `_redirects`.

## IndieWeb & ActivityPub

- microformats2: `h-card` (footer), `h-entry` (news pages), `h-feed` (home page).
- Webmentions via [webmention.io](https://webmention.io): log in there once with `https://instytut.14-200.pl` (uses the `rel=me` links). Mentions are shown under each news post.
- Feeds: `/feed.xml` (Atom), `/feed.json` (JSON Feed).
- Fediverse: the account `@instytut@14-200.pl` on the 14-200.pl hub (GoToSocial), no Bridgy Fed.
  Plan: `14-200.pl/docs/plan-instytut.md`. Until the account exists, `site.fediverse.active` is `false`
  and `/fediverse/` says "w przygotowaniu". Set it to `true` when the account works.
